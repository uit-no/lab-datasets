{{ icon("server") }} How a new version goes live

The app runs on Azure App Service (p-resapp-labdata-webapp, run by UiT IT, contact Rolf Andersen) with two slots: staging for testing and production for everyone. Pushing to GitHub does not deploy anything by itself.

  1. Push the code to main of uit-no/lab-datasets.
  2. Deploy to staging: run Deploy labcat to Azure staging (Run workflow, branch main). It runs the tests first and takes about 2 minutes.
  3. Check staging: it shows a yellow “Test copy” banner. Look around, but don't edit: the swap takes staging's files along, so test edits would reach production and GitHub.
  4. Swap: run Swap labcat staging to production. The two slots trade places, code and files included.
  5. Check production: no banner, the catalog is there, and this page says In sync. Staging now runs the previous version until the next deploy.
{{ icon("sliders-horizontal") }} Server settings (App Service → Environment variables)
Both slots
LABCAT_SLACK_CLIENT_ID, LABCAT_SLACK_CLIENT_SECRET, LABCAT_SLACK_TEAM_ID, LABCAT_SECRET_KEY, LABCAT_ADMINS, LABCAT_DATA_REMOTE, LABCAT_GIT_TOKEN
Per slot
LABCAT_BASE_URL (the slot's own address), LABCAT_DATA, and LABCAT_SANDBOX=1 on staging only. These are marked as deployment slot settings so they stay put during a swap.

If LABCAT_DATA holds a checkout of another repository (or none), the app renames it to ….old-<time> at startup and clones the data repository fresh.

{{ icon("circle-help") }} When something goes wrong
  • Empty catalog: look at the sync box above. “No GitHub remote” means LABCAT_DATA_REMOTE is missing on that slot.
  • Clone or sync fails with 403: the token lacks access to the data repository. It needs resource owner cogneuro-uit, the repository lab-datasets-data and Contents: Read and write.
  • Slack says “redirect_uri did not match”: add <address>/auth/callback to the Slack app's redirect URLs and save.
  • App doesn't start: the Log stream in the Azure portal shows the reason, e.g. a missing setting.
